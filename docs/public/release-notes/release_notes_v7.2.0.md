# Release v7.2.0 — Music Video Generation: Turn a Song into an AI Music Video with a Consistent Singer

> Release date: 2026-10-10

## Overview

v7.2.0 is a **minor release** that adds a whole new creation mode: **AI music video generation**. Upload a song and the app splits it into 10-second segments, generates one AI video clip per segment, and renders a finished music video whose only audio track is your original song. Lyrics are recognized locally and can be burned in as lyric subtitles. On top of that, you can now keep **one consistent performer** across the entire video — either from your own photo or generated by AI from a text description — and every task writes a readable `storyboard.json` you can download and inspect.

This release consolidates the v7.1 (song → music video) and v7.2 (singer / performer + storyboard) development increments, which were merged into `master` without a release being cut in between.

## Usage

From v7.0.5:

```bash
git pull
./start.sh
```

Docker users: `docker pull ghcr.io/lcy362/free-short-video:7.2.0` (then `docker compose up -d` to recreate the container).

npm users: `npx free-short-video` or `npm install -g free-short-video`.

**Upgrade notes**

- **First music video downloads a model.** Lyric recognition runs on faster-whisper (`small` by default, a few hundred MB). It is downloaded on the first music video task only; the progress panel shows a dedicated "downloading lyric model" step, and `AGNES_LYRICS_MODEL` lets you pick a different model size.
- **Lyric recognition is optional.** If recognition fails, or the track is instrumental, the task still completes — you just get the video without lyric subtitles.
- **New optional dependency.** `faster-whisper` (and `av`) is imported lazily, only when lyric recognition actually runs; a missing or broken install never prevents the app from starting. The Docker image grows by roughly 100 MB (models are not bundled; they are cached in the container's `HF_HOME`).
- **No breaking changes and no migration.** Existing tasks, checkpoints and configuration files stay valid, and the new singer options default to `none`, which is exactly the previous behavior.

## What's New

### Features & Improvements

* **Music video generation — a new creation mode.** Upload a song (MP3, WAV, M4A, AAC, OGG, FLAC or OPUS; up to 50 MB and 5 minutes, at least 10 seconds) and get a music video back. The song is split into 10-second segments — a 5-minute song becomes 30 clips — and each segment receives its own AI-generated scene prompt that follows what happens in that part of the song. A style preset or your own style text applies to every clip.
* **Your song is the soundtrack.** The final video uses the uploaded song as its only audio track: no text-to-speech narration, and no volume amplification, so the mix you mastered is the mix you get.
* **Automatic lyric recognition with lyric subtitles.** Lyrics are transcribed locally with faster-whisper (CPU, `small` by default) and can be burned into the video as subtitles. Hallucinated and low-confidence lines are filtered out; if recognition fails or the song has no vocals, the video is still produced without subtitles.
* **A consistent singer or performer across every clip (new).** Music videos now take a performer reference image (`singer_mode`): `none` for the previous behavior, `photo` to upload your own picture (EXIF-rotated and downscaled to 2048 px), or `ai` to describe the performer in up to 500 characters and have the Agnes image model generate the portrait. Whichever you choose, that single image is submitted as the reference image of **every** segment, so the same person appears from the first clip to the last instead of drifting between clips.
* **A downloadable storyboard for every music video (new).** Each task writes a human-readable `storyboard.json` that lines up the exact time spans, the recognized lyric lines for each span and the generated scene visuals. It is exposed as a read-only artifact in the task's artifact list, and it is backfilled from the task state when an older task is resumed, so pausing and resuming never leaves you without one.
* **Performer-aware scene prompts.** Scene prompt generation accepts an optional performer description and weaves it into every clip's prompt. With no performer set, prompts stay byte-identical to the previous behavior.
* **Strict upload validation with clean rollbacks.** `POST /api/tasks/music-video` validates the song (extension, 50 MB cap, 10–300 s duration, actually readable) and the singer input (mode whitelist, description required and ≤500 characters, photo extension) *before* anything is written to disk, and already-staged uploads are removed again if a later check fails — no orphaned files on your disk.
* **Resumable like every other multi-scene mode.** Finished clips are reused on resume, so a 30-clip music video that dies at clip 27 continues from clip 27 instead of paying for 27 clips again.
* **Localized in all 22 UI languages** — the music video tab, its progress timeline and the new singer options ship translated everywhere.

### Refactoring & Optimizations

* **The storyboard costs no extra model call.** It is assembled deterministically from data the pipeline already holds (time spans, recognized lyrics, generated prompts) rather than asking the LLM for another pass, and it is reconstructed from task state on resume — no duplicated work and no extra cost per task.
* **One shared audio-overlay path, now volume-aware.** The compositor's `audio_overlay` helper takes an explicit `audio_volume`, so text-to-speech callers keep their 1.5× loudness compensation while music passes 1.0 and is never amplified.

---

**Good to know before you start a long song:** music videos share the video API rate limit with the other modes — one submission per minute per API key by default (`AGNES_VIDEO_RATE_LIMIT`), so a 5-minute song needs at least ~30 minutes of submission time before rendering finishes. Adding more API keys scales that linearly. And please only upload audio you hold the rights to.
